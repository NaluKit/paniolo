# Calculation corpus

Counterexamples for the optional calculation check (`Paniolo.Builder.calculationCheck(true)`,
CLI `--calculation-check`). Each case breaks exactly one amount relationship of a valid base
invoice and exists in three targets:

| Target            | Syntax | Rules applied                                   |
|-------------------|--------|-------------------------------------------------|
| `xrechnung-cii`   | CII    | EN 16931 and XRechnung 3.0.2 (incl. Peppol rules) |
| `xrechnung-ubl`   | UBL    | EN 16931 and XRechnung 3.0.2 (incl. Peppol rules) |
| `facturx-en16931` | CII    | Factur-X 1.09.2 profile EN 16931                 |

Base invoice: one line 2 x 100.00 (gross price 120.00 minus discount 20.00), a document allowance
of 10 % of 200.00, 19 % VAT; line total 200.00, tax basis 180.00, VAT 34.20, amount due 214.20.

| Case                   | Change                                                       |
|------------------------|--------------------------------------------------------------|
| `valid`                | none                                                         |
| `line-net-amount`      | line net amount 210.00 instead of 2 x 100.00, totals consistent with it |
| `net-price`            | price discount 10.00, so gross minus discount is not the net price |
| `allowance-percentage` | allowance percentage 5 % instead of 10 % of 200.00           |
| `line-total`           | sum of line net amounts (BT-106) 201.00                      |
| `tax-total`            | total VAT amount (BT-110) 34.30                              |
| `payable-amount`       | amount due (BT-115) 215.00                                   |
| `vat-category-amount`  | VAT category amount 34.21 and the totals following it        |

`expected.csv` lists for every file the official findings (rule and severity, without
information) and the findings of the calculation check (rule, location, severity). A calculation
finding is `WARNING` if no official rule reports the same relationship, and `INFO` if one does
(the message then names it) or if the difference is within the VAT rounding the official rules
accept. `vat-category-amount` states 34.21 instead of 34.20: a difference within the rounding of
its lines (0.01 per line, BR-FXEXT-S-09), which the readers keep as stated VAT amount
(`Invoice.vatAmounts()`), so the totals agree and there is no finding.

The files are generated by `CalculationCorpus` (test sources); `CalculationCorpusTest` checks that
they are up to date and that the findings match `expected.csv`. The XML files contain no
Paniolo-specific content and can be validated with other tools to compare their findings.
