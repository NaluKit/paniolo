Paniolo compared with Java libraries for e-invoicing

As of 28 November 2026 · Paniolo 1.1.0 · Mustangproject 2.26.0 · Comparison of documentation and sources; no new joint runtime or conformance test

Paniolo covers a large part of invoice processing. The clearest gaps are additional national formats, a broader validation catalogue and general PDF functions. Its strengths are the invoice model, direct UBL and CII writers, traceable import handling and the browser viewer.

5. Documented strengths of Paniolo

Compared with invoice4j, no documented additional invoice function that Paniolo lacks was found. Calculation, CII/UBL, XRechnung validation and hybrid PDFs are shared. Paniolo's additional documented areas: quotations, orders, delivery notes, import deviations and the viewer. This says nothing about the quality of individual field mappings.

6. Further limits of Paniolo

  • No complete model of every valid document: for example, tax category B is currently not supported. Successful XML validation and successful model import are different checks.
  • Order-X EXTENDED is written with the COMFORT content, not with all EXTENDED fields.
  • Delivery notes: certain dangerous-goods, packaging and transport details are missing.
  • Peppol despatch advice rules must be provided separately (no published licence).
  • EN 16931:2026 / XRechnung 4.0 are not supported. Technical support for new schemas in other libraries is not the same as complete business rule validation.
  • The browser viewer displays validation results but does not run invoice validation in the browser itself.
