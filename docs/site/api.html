Reproducible quickstart

The quickstart creates one invoice, writes and validates it as both UBL and CII, reads it back, and checks its amount due. Dates, amounts, artifact versions and Maven plugin versions are fixed. The output XML is for demonstration; replace the example parties and identifiers before use. This reproduces API behavior and semantic results, not byte-identical Maven archives or report timestamps across machines.

1. Prepare the pinned source

Requirements: JDK 21, Maven 3.9.9, Git, and a POSIX shell with tar and mktemp (Linux or macOS). The first Maven build needs network access for dependencies and checksum-verified rule bundles. Invoice processing after the build needs no network connection.

Run the following from the root of an existing Paniolo clone containing the commit above. All shell steps in this quickstart use the same terminal session. git archive exports the committed source into a new temporary directory without changing your current branch or files. If the commit is not available locally, fetch the repository revision containing it first.

set -eu
java -version
mvn -version

git cat-file -e 6c2d2dc169afa7bf266fa7feb36a7a5f296e67ad^{commit}
PANIOLO_QUICKSTART_DIR=$(mktemp -d "${TMPDIR:-/tmp}/paniolo-quickstart.XXXXXX")
mkdir -p "$PANIOLO_QUICKSTART_DIR/source"
git archive 6c2d2dc169afa7bf266fa7feb36a7a5f296e67ad \
  | tar -x -C "$PANIOLO_QUICKSTART_DIR/source"

mvn -B -ntp -f "$PANIOLO_QUICKSTART_DIR/source/pom.xml" \
  -Drevision=0.0.0-6c2d2dc169af install

mkdir -p "$PANIOLO_QUICKSTART_DIR/app/src/main/java/example"
cd "$PANIOLO_QUICKSTART_DIR/app"

The install runs the library's tests and installs its modules into your local Maven repository. It does not deploy anything. Keep the printed temporary directory path if you want to return to the example later; echo "$PANIOLO_QUICKSTART_DIR" shows it.

3. Create the invoice application

Save this complete class as src/main/java/example/Quickstart.java in the same app directory. No imports or helper objects are omitted.

package example;

import io.github.nalukit.paniolo.Paniolo;
import io.github.nalukit.paniolo.config.InvoiceSyntax;
import io.github.nalukit.paniolo.model.Invoice;
import io.github.nalukit.paniolo.model.common.Address;
import io.github.nalukit.paniolo.model.common.Contact;
import io.github.nalukit.paniolo.model.common.CreditTransfer;
import io.github.nalukit.paniolo.model.common.DeliveryInformation;
import io.github.nalukit.paniolo.model.common.ElectronicAddress;
import io.github.nalukit.paniolo.model.common.InvoiceLine;
import io.github.nalukit.paniolo.model.common.Party;
import io.github.nalukit.paniolo.model.common.PaymentInstruction;
import io.github.nalukit.paniolo.model.common.TaxCategory;
import io.github.nalukit.paniolo.model.common.value.Country;
import io.github.nalukit.paniolo.model.common.value.PaymentMeansCode;

import java.math.BigDecimal;
import java.nio.file.Files;
import java.nio.file.Path;
import java.time.LocalDate;

public final class Quickstart {
  public static void main(String[] args) throws Exception {
    var seller = Party.create()
                      .name("Muster GmbH")
                      .address(new Address("Musterstraße 1", "Berlin", "10115", Country.DE))
                      .vatId("DE123456788")
                      .electronicAddress(new ElectronicAddress("rechnung@example.org", "EM"))
                      .contact(new Contact("Erika Muster", "+49 30 123456", "rechnung@example.org"))
                      .build();
    var buyer = Party.create()
                     .name("Kunde GmbH")
                     .address(new Address("Kundenweg 2", "Hamburg", "20095", Country.DE))
                     .electronicAddress(new ElectronicAddress("einkauf@example.org", "EM"))
                     .build();
    var payment = PaymentInstruction.create()
                                    .meansCode(PaymentMeansCode.CODE_58)
                                    .addCreditTransfer(CreditTransfer.create()
                                                                     .iban("DE89370400440532013000")
                                                                     .accountName("Muster GmbH")
                                                                     .bic("COBADEFFXXX")
                                                                     .build())
                                    .remittanceInformation("R-2026-001")
                                    .build();
    Invoice invoice = Invoice.create()
                             .number("R-2026-001")
                             .issueDate(LocalDate.of(2026, 10, 27))
                             .dueDate(LocalDate.of(2026, 11, 10))
                             .delivery(DeliveryInformation.create()
                                                          .actualDeliveryDate(LocalDate.of(2026, 10, 26))
                                                          .build())
                             .buyerReference("04011000-12345-03")
                             .seller(seller)
                             .buyer(buyer)
                             .paymentInstruction(payment)
                             .addLine(InvoiceLine.create()
                                                 .id("1")
                                                 .name("Beratung")
                                                 .quantity(new BigDecimal("2"))
                                                 .unitCode("HUR")
                                                 .netUnitPrice(new BigDecimal("100.00"))
                                                 .tax(TaxCategory.standard(new BigDecimal("19")))
                                                 .build())
                             .build();

    Paniolo paniolo = Paniolo.create();
    Path output = Path.of("target", "invoices");
    Files.createDirectories(output);
    for (InvoiceSyntax syntax : InvoiceSyntax.values()) {
      byte[] xml = paniolo.toBytes(invoice, syntax);
      var result = paniolo.validate(xml);
      if (!result.isValid() || result.hasWarnings()) {
        throw new IllegalStateException(result.toXml());
      }
      Invoice received = paniolo.read(xml);
      if (!invoice.number().equals(received.number())
          || received.totals().payableAmount().compareTo(new BigDecimal("238.00")) != 0) {
        throw new IllegalStateException("Unexpected round-trip result for " + syntax);
      }
      Files.write(output.resolve("invoice-" + syntax.name() + ".xml"), xml);
      System.out.println(syntax + ": valid, warnings=false, number=" + received.number()
          + ", payable=" + received.totals().payableAmount().toPlainString() + " EUR");
    }
  }
}

The builder defaults to EUR, document type 380, and the XRechnung process identifiers. Two hours at EUR 100.00 plus 19% VAT result in EUR 238.00. The checks use BigDecimal.compareTo so decimal scale differences do not change the result.

4. Compile and run

Still in the app directory:

mvn -B -ntp compile \
  org.apache.maven.plugins:maven-dependency-plugin:3.7.0:copy-dependencies \
  -DincludeScope=runtime
java -cp 'target/classes:target/dependency/*' example.Quickstart

Expected standard output (JVM diagnostics may additionally appear on standard error):

UBL: valid, warnings=false, number=R-2026-001, payable=238.00 EUR
CII: valid, warnings=false, number=R-2026-001, payable=238.00 EUR

The example writes target/invoices/invoice-UBL.xml and target/invoices/invoice-CII.xml. Any validation error, warning or failed round-trip check terminates the process with an error. Once the application is compiled and the dependencies have been copied, the java command also works without network access. XML output does not require any PDF or JSON modules.

Facade reference

The entry point is io.github.nalukit.paniolo.Paniolo. Create one instance and reuse it. Writers and readers do not compile validation rules. Validators are initialized lazily and cached per facade; warmUp() prepares the XRechnung invoice validators.

read accepts UBL Invoice/CreditNote, CII, ZUGFeRD 1.0 XML and supported invoice PDFs. It does not replace validation. ReadMode.STRICT rejects inconsistent amounts; LENIENT can adapt supported amount deviations and returns them in ReadResult.warnings(). Preserve original input bytes when you need an unchanged source document, or use importInvoice, which keeps them in the ImportResult. ReadResult.isExact() means no accepted amount deviations were reported; it does not promise byte-identical XML or complete support for arbitrary extensions.

Automatic validation selects rules from the specification identifier (BT-24) and PDF metadata. The overload with ValidationProfile.Syntax deliberately bypasses profile detection and always uses the EN 16931/XRechnung rules for that syntax. Use the automatic overload for Factur-X profiles and the XRechnung extension. By default, the detecting overloads throw an IllegalArgumentException for a document whose type they cannot detect; Builder.unknownDocuments(UnknownDocumentHandling.REPORT_INVALID) returns an invalid result with the FATAL finding XML-PARSE or PANIOLO-UNKNOWN-DOCUMENT instead.

A supplied PDF must already be PDF/A and contain the visual document; Paniolo does not convert arbitrary PDFs into compliant PDF/A. Without a PDF of your own, the rendering overloads create the pages with paniolo-pdf-layout (DIN 5008, German, English and French, logo, own fonts); PdfLayout.of(locale) and its with... methods configure them. Model reference

Model packages start with io.github.nalukit.paniolo.model. Records are immutable; mutable builders are for one operation/thread. Prefer Type.create()...build() for named construction. Constructors and builders enforce structural checks; validation against the official XML rules is separate. JavaDoc documents record components with BT/BG references where applicable.

Use decimal strings such as new BigDecimal("19") instead of binary floating-point constructors. Use LocalDate for document dates. Code-list factories such as UnitCode.of("HUR") return null for unknown values; check the result before passing it to a required model field.

ValidationResult.messages(stage)Findings of a single stage

ValidationMessage.StageXML, XSD, SCHEMATRON, PDF_A, HYBRID, CALCULATION

NullPointerExceptionA required API argument is null
IllegalArgumentExceptionUnprocessable input, unsupported content or failed model constraints; auto-detection may reject malformed XML
IllegalStateExceptionA PDF operation needs an optional module that is not on the classpath
ValidationExceptionBroken validation configuration or execution failure; distinct from an invalid invoice
UncheckedIOExceptionAn underlying input/output operation failed

A valid result is not proof that every possible stage ran. Without paniolo-pdfa, PDF validation includes PDFA-NOT-CHECKED; without configured Peppol rules it includes PEPPOL-RULES-NOT-CHECKED. CIDA reports CIDA-NOT-CHECKED. Decide which stages and findings your application requires. XSD failure skips Schematron execution. Rule bundles are trusted application resources; local imports and declared lookup documents are restricted to configured resources, and rules are not downloaded during validation.

With calculationCheck(true), invoice validations also recalculate the amounts and report differences in the stage CALCULATION with rule IDs starting with PANIOLO-CALC-. These findings are warnings or information and never change isValid(). Which warnings a receiving process must not accept is decided separately with AcceptancePolicy.officialRules().rejectOn(ruleIds...) or rejectOnWarnings(); the official result stays unchanged.

For direct validation without the facade, create an InvoiceValidator from a ValidationProfile and reuse it. ValidationProfile describes local XSDs, compiled Schematron XSLTs, severity overrides and permitted lookup documents. Raw .sch sources are not compiled by this API. See the validation module for factories and report structure.

The XRechnung, Factur-X, French and Order-X defaults are packaged dependencies. The Peppol Despatch Advice rules have no published license and must be obtained separately and configured. Rule paths must remain available while the facade is in use. Builders themselves are not thread-safe.

To add PDF, rendering or JSON support to the example POM, add the corresponding artifact with group ID io.github.nalukit and version 0.0.0-6c2d2dc169af. No explicit registration is needed for the PDF providers. Add both paniolo-facturx and paniolo-pdfa to include PDF/A checking, and paniolo-pdf-layout (which brings paniolo-facturx) to create PDFs without a PDF of your own.

PanioloVisualizer.create().toHtml(document) writes a standalone HTML page that shows an invoice, order or despatch advice with the web component <paniolo-viewer>; web applications load the component from /paniolo-visualizer/paniolo-visualizer.js in the artifact. See the visualizer module. MustangInvoiceAdapter.create().map(transaction) maps a Mustang invoice to the model and lists every value it cannot carry over; see the Mustang module.

PanioloJson.create() is the JSON entry point. toJson, toPrettyJson and toBytes serialize the model; read(input, Invoice.class) also accepts Order.class and DespatchAdvice.class. The JSON is Paniolo's storage format and follows this model version, not a standardized invoice exchange format. Loading performs model checks. See the JSON module.
